# Sparse numerical reference data

- `scipy.json`: generated only by `tests/reference/sparse_scipy.py`, seed
  20261104, using NumPy 2.3.5 / SciPy 1.17.1. Contains canonical real CSR arrays,
  RHSs, independent SciPy CG solutions and sparse matrix-vector products for
  deterministic SPD matrices (n=9/12/48, scales 1 and 1e±100), plus Dirichlet
  Poisson n=31/32/63 with explicit Jacobi reference solves. No implementation
  source is copied from NumPy or SciPy; their BSD licenses remain with those
  development tools. Ordinary tests use this JSON without either dependency.
- `testdata/fuzz/FuzzCGDiagonal/72a9bf01bbee2062`: regression for the test's
  former overly strict bitwise-equality assertion. A normalized search direction
  introduces normal floating-point rounding; vector values are now compared
  with a small numerical tolerance. This corpus is intentionally under central
  tests, never in production sparse/testdata.

The test TestMain changes working directory here, including when using overlays,
so new fuzz failure corpora also remain in this directory.

- `product.json`: generated by `tests/reference/sparse_product.py`, independent
  NumPy 2.3.5 / SciPy 1.17.1 CSR products plus exact Python Fraction products of
  the actual binary64 inputs. Five SciPy shape/random cases and seven Fraction
  cases cover overflowing-product cancellation, underflowing-product accumulation
  to a subnormal, exact zero cancellation, mixed scale/rounding, explicit zeros,
  and rejected final overflow/nonzero underflow. Fraction output values include
  exact rational strings and independently rounded IEEE-754 bits. Ordinary tests
  need neither SciPy nor Python. No third-party source is copied.

- `bicgstab.json`: generated by `tests/reference/sparse_bicgstab.py`, independent
  NumPy 2.3.5 / SciPy 1.17.1 BiCGSTAB and sparse-direct solutions for eleven
  nonsymmetric, nonnormal, negative-diagonal, Jacobi and `1e±300`-scale systems.
  Extreme reference solves use an explicitly scaled equivalent system; original
  scaled CSR/RHS arrays are stored for Go. No source is copied from either tool;
  their existing BSD notices remain with the installed development tools.
  Ordinary tests use JSON only. BiCGSTAB fuzz failures are also rooted here by
  the existing central TestMain, never under a production testdata directory.
